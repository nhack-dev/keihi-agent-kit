# 領収書の記録の型（エージェントが画像・PDF を見て書く）

1枚1行の JSON を `data/ryoushuu.jsonl` に足します。読めない項目は**空のまま**にし、`yomenai` に理由を書きます。推測で埋めません。

```json
{"file": "data/ryoushuu/2026-09/IMG_0001.jpg", "date": "2026-09-02", "amount": 1480, "mise": "見本タクシー", "invoice_no": "T0000000000001", "uchiwake": {"10": 1480}, "naiyou": "移動", "shiharai": "見本カード", "dousekisha": "", "yomi": "高", "yomenai": ""}
```

| 項目 | 書くこと |
|---|---|
| file | 画像・PDF の置き場（`data/` の下） |
| date | 取引の日（YYYY-MM-DD）。発行日と利用日が違えば利用日 |
| amount | 支払った税込の合計（整数・円） |
| mise | 発行元の名前（領収書のとおり） |
| invoice_no | 登録番号（T＋13桁）。無ければ空 |
| uchiwake | 税率ごとの税込の額 `{"10": 円, "8": 円}`。書いてあるときだけ |
| naiyou | 何を買ったか（但し書き・品目） |
| shiharai | 払い方（カード名・「現金」など。config/kaikei.json の kouza の名前） |
| dousekisha | 飲食で一緒だった人（オーナーが書いてよいと言った範囲だけ。名前でなく「取引先2名」などでもよい） |
| yomi | 読みの確からしさ 高／中／低 |
| yomenai | 読めなかった所・怪しい所 |

## 読み直しの手順（必ず）

1. 金額は2回読む。合計の欄と、明細の足し算が合うかを見る
2. 日付の年を確かめる（和暦・2桁の年に注意）
3. 登録番号は T のあとの数字が13桁あるか数える
4. 1枚に複数の取引がある（レシートが2枚写っている等）ときは、1件ずつ別の行にする
5. かすれ・折れ・手書きで読めない所は、空にして `yomi: "低"`
